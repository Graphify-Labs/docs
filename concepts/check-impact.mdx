Before you change a function or a file, ask your agent what the change reaches. Graphify reads the graph of your indexed repository and returns the connected code, the files where a change fans out most widely, and the tests linked to them.

Use this while you plan a change. After you open a pull request, [pull request reviews](/platform/reviews) check the change itself.

## Before you start

- An account at [app.graphify.com](https://app.graphify.com). New accounts start on a 14-day Pro trial, then Free (up to 3 repositories), no card required.
- A repository with the status **Indexed**. See [Repositories and builds](/platform/repositories).
- Your agent connected to the hosted MCP server at `https://api.graphify.com/mcp`. See [Code with an agent](/cookbooks/cloud-coding-agents).

## Ask about the change

<CodeGroup>

```text Agent prompt
Use Graphify on Graphify-Labs/graphify: I want to change build_from_json.
What does that change reach, which files are riskiest, and which tests cover them?
```

</CodeGroup>

Name the symbol or the file you plan to change. Your agent uses these hosted tools:

| Tool | What it returns |
| --- | --- |
| `graphify_impact` | The code directly connected to a symbol. A first pass at what a change reaches. |
| `impact_and_risk` | Files ranked by how widely a change fans out, and whether tests cover them. |
| `graphify_tests_for` | Tests linked to a symbol or a file. |
| `graphify_file_neighbors` | A file's imports, and the files that import it. |

For a deeper look, ask for the callers of the symbol. See [Follow calls and trace a path](/concepts/follow-calls).

## Read the result

Treat the result as a starting list, not a full answer:

- `graphify_impact` returns direct connections only. Code that is called dynamically, or connected through several steps, may not appear.
- A file with no linked tests in the result may still be tested in a way the graph does not link.
- Each edge carries a confidence tag (`EXTRACTED`, `INFERRED`, or `AMBIGUOUS`). [Edges and provenance](/concepts/provenance) explains each tag.

Read the code your agent lists before you change it.

## If something fails

| What you see | What to do |
| --- | --- |
| The wrong symbol is used | Give the full name or the file it lives in. |
| Very few results | Check that the latest build is **Indexed**, then ask for callers to go further. |
| No tests listed | Ask your agent to search the test folders, then run the tests you find. |
