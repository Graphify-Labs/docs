Two pull requests can both pass review and still collide when they change the same part of the code. Graphify compares open pull requests against the graph of your repository and shows which ones touch the same area, so you can review and merge them with that in mind.

## Before you start

- An account at [app.graphify.com](https://app.graphify.com). The Free plan (up to 3 repositories) needs no card. Pro and Teams start with a 14-day trial, card required.
- For the local commands, the open-source CLI. See [Installation](/open-source/installation).
- A repository with the status **Indexed**, or a local graph at `graphify-out/graph.json`.
- For the local commands, the [GitHub CLI](https://cli.github.com) signed in to the repository. `graphify prs` reads open pull requests through it.

## In Graphify

On a connected repository, Graphify checks each pull request for cross-branch conflicts with the other open pull requests and gives a merge order. It does this along with the [review](/platform/reviews) of each pull request. Like the review, it is advisory and doesn't block a merge.

## With the local CLI

From the repository root, list the open pull requests that share a graph community:

```bash
graphify prs --conflicts
```

The output groups pull requests by community, with the number of pull requests that overlap in each. This is a merge-order *risk* signal. It does not give a merge order, and it does not promise a textual conflict or a runtime break. If no open pull requests overlap, the command says so.

To have a model rank the review queue:

```bash
graphify prs --triage
```

Triage uses the first model backend it finds configured. Set `GRAPHIFY_TRIAGE_BACKEND`, and optionally `GRAPHIFY_TRIAGE_MODEL`, to choose one.

| Option | Meaning |
| --- | --- |
| `--conflicts` | Group open pull requests that share a graph community. |
| `--triage` | Rank the review queue with a model. |
| `--base <branch>` | Only pull requests that target this branch. Defaults to the repository's default branch. |
| `--repo <owner/name>` | Read pull requests from another repository. |
| `--graph <path>` | The graph file to use. |
| `<number>` | Show one pull request with its graph impact. |

For example, on a clone of the open-source repository:

```bash
git clone https://github.com/Graphify-Labs/graphify && cd graphify
graphify extract . --code-only
graphify prs --conflicts --repo Graphify-Labs/graphify
```

## Read the result

Pull requests in the same community change code that is closely connected in the graph. Review them together and agree an order. After each merge, rebase the others and run your tests. A pull request missing from the list can still conflict in ways the graph does not show, such as config or generated files.

## If something fails

| What you see | What to do |
| --- | --- |
| "No graph impact data" | Build or point to a graph: run `graphify extract . --code-only`, or pass `--graph`. |
| No pull requests listed | Check `--base`. Only pull requests that target that branch are compared. |
| An error from `gh` | Sign in with `gh auth login` and check you can see the repository. |
| Triage can't find a backend | Set `GRAPHIFY_TRIAGE_BACKEND` and the API key for that backend. |

[Pull request context](/open-source/features/pr-impact) covers the rest of `graphify prs` and the MCP tools for pull requests.
