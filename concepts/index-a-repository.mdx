Indexing turns a repository into a graph that Graphify and your agent can query. Connect the repository, switch on indexing, and wait for the status **Indexed**. After that, each push to the default branch updates the graph.

## Before you start

- An account at [app.graphify.com](https://app.graphify.com). The Free plan (up to 3 repositories) needs no card. Pro and Teams start with a 14-day trial, card required.
- Permission to grant the Graphify app access to the repository on GitHub or GitLab.

## Index the repository

<Steps>
  <Step title="Connect the repository">
    Open **Repositories** and click **Add GitHub repositories**, or click **Connect** on the GitLab card in **Connectors**. Grant access to the repositories you want in the provider's flow.

    A newly connected repository shows **Paused** and **Not indexed**. Nothing is indexed until you switch it on.
  </Step>
  <Step title="Switch on indexing">
    Open the repository's **…** menu and switch on **Indexing**. This queues the first build. You can also click **Index** next to the repository card on **Overview**.
  </Step>
  <Step title="Follow the build">
    Open **Builds** and filter by the repository. When the build finishes, the repository shows **Indexed**.
  </Step>
  <Step title="Check the graph">
    Open **Graphs** and choose the repository to see its nodes and most connected areas.
  </Step>
</Steps>

To try it on a public codebase, index a fork of [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify).

<Accordion title="Build the graph locally instead">
  The open-source CLI builds the same kind of graph on your machine, with no account:

  ```bash
  uv tool install graphifyy
  graphify install
  ```

  `graphify install` sets up Claude Code. Every other assistant has its own command on its [integration page](/integrations/overview). Then send `/graphify .` in your assistant's chat. The graph is written to `graphify-out/graph.json`. See [Your first knowledge graph](/open-source/quickstart).
</Accordion>

## What updates the graph

| Event | What happens |
| --- | --- |
| A push to the default branch | Graphify indexes that commit. |
| A push to any other branch | Nothing. The graph follows the default branch only. |
| A pull request | No new graph. The review uses the default-branch graph and the pull request's diff. |
| **Retry** on a failed build | Graphify indexes the current head of the default branch. |

One index of a repository runs at a time. A later push waits, or joins the build already queued. Hosted plans can limit how many push-triggered indexes finish in a UTC day; a manual reindex does not count. See [Plans and pricing](/platform/support/pricing).

## If something fails

| What you see | What to do |
| --- | --- |
| The repository is not in the list | Grant the Graphify app access to it on GitHub or GitLab, then return to **Repositories**. |
| You can't switch on indexing | On Free, check that fewer than 3 repositories are indexed. |
| The status is **Failed** | Open **Builds**, read the failed run, then choose **Retry**. |
| The status is **Out of date** | The newest default-branch commit is not the one the graph serves, and no build is running. Start a reindex. |

[Repositories and builds](/platform/repositories) covers every status and control.
