Graphify reviews a pull request against the graph of your repository, so a finding can point past the diff to the callers and dependencies a change reaches. You read the review in **Reviews**, rerun it with a comment, and tell it which findings were right.

Reviews are advisory. They don't block a merge.

## Before you start

- An account at [app.graphify.com](https://app.graphify.com). New accounts start on a 14-day Pro trial, then move to Free (up to 3 indexed repositories). No card is required.
- A repository with the status **Indexed**. See [Repositories and builds](/platform/repositories).
- **PR reviews** switched on for the repository. It is on unless someone turned it off in **Repositories** > **Options**.

## Get a review

Open a pull request, reopen one, or mark a draft as ready for review. Graphify reviews it at that point. A draft is skipped until it is marked ready.

A later push to the pull request does not start another review. To review the current head after new commits, comment on the pull request:

```text
@graphify review
```

The comment works for a repository owner, member, or collaborator. The review uses the indexed default-branch graph plus the pull request's diff. It does not index the pull request's branch.

## Read the review

1. Open **Reviews** and choose the repository.
2. Select the pull request and the review run. Check the commit, so you know which revision was reviewed.
3. Read each finding with its source context and the affected code.

The review can also include these advisory sections, each with its own switch in **Repositories** > **Options**:

| Section | What it lists |
| --- | --- |
| **Risky patterns (advisory)** | Risky patterns on lines the pull request adds. |
| **Docs that may be stale (advisory)** | Docs that mention code the pull request changed. |

Where formal verification ran, each supported changed function gets a result: proved equivalent, a behavior change with the input that shows it, or no verdict. A finished review is not proof that the change keeps behavior. See [Read a review and a verdict](/platform/read-a-result).

## Tell Graphify what was right

Reply on the pull request with the exact finding or rule name from the review:

| Comment | Use it when |
| --- | --- |
| `@graphify wrong <finding>` | The finding is a false positive. |
| `@graphify good <finding>` | The finding was useful. |
| `@graphify suppress <rule>` | You want Graphify to stop surfacing findings from that rule. |

Feedback changes which advisory findings appear later. It does not change verification results. The [Learn](/platform/learning) view shows the dismissals, suppressed patterns and feedback history.

## If something fails

| What you see | What to do |
| --- | --- |
| No review on a new pull request | Check that **PR reviews** is on and the repository is **Indexed**. A draft waits until it is marked ready. |
| The review is for an old commit | Comment `@graphify review` to review the current head. |
| `@graphify review` does nothing | The commenter must be an owner, member, or collaborator, and **PR reviews** must be on. |
| A finding misses recent default-branch code | The graph may be **Out of date**. Check [Repositories and builds](/platform/repositories). |
