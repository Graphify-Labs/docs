Connect [Claude Code](https://code.claude.com/docs/en/overview) to Graphify's hosted MCP server at `https://api.graphify.com/mcp`. Claude Code can then search the repositories indexed in your [Graphify](https://app.graphify.com) workspace, follow callers and dependencies, and check what a change reaches.

The server uses Streamable HTTP and OAuth. There is no API key to paste.

For Claude.ai, the desktop chat app, and mobile, use [Graphify for Claude](/integrations/claude-ai). Connecting there with the same Claude account can also show Graphify in Claude Code under `/mcp`.

<InstallButton href="https://claude.ai/directory/graphify" label="Connect in Claude">
Optional: connect Graphify in the Claude directory with your Claude account, then open /mcp in Claude Code.
</InstallButton>

## Before you start

- A Graphify account. If you don't have one yet, you can create one for free while connecting. The Free plan needs no card. See [Plans and pricing](/platform/support/pricing).
- At least one repository with the status **Indexed**. The [quickstart](/platform/quickstart) connects GitHub and starts indexing. Indexing status is on [Repositories and builds](/platform/repositories).

## 1. Attach Graphify

### Use your claude.ai connector

If Claude Code is signed in with the same Claude account, open `/mcp`. Connectors from claude.ai appear in that list. Complete authentication if it still needs it, then ask Claude Code to list your Graphify repositories.

Those connectors load only for a Claude account login. They do not load when `ANTHROPIC_API_KEY`, Bedrock, or another provider is the active login. Run `/status` if `/mcp` does not list the connector, then `/login` with your Claude account, or add the server as below.

### Add the server in the terminal

Use this when Claude Code is not using your Claude account, or when you want a local entry. Run it in a terminal, not inside a Claude Code session. The command is user scope. Graphify still requires OAuth. There is no API key to paste.

```bash
claude mcp add --transport http --scope user graphify https://api.graphify.com/mcp
```

`--scope user` adds Graphify for your user, so it works in every project. The hosted server is per account, not per repository. To keep it to one folder, drop `--scope user` and Claude Code uses local scope.

If a local entry and a claude.ai connector point at the same URL, Claude Code keeps the local entry and lists the connector as hidden. Use one path.

To share the server with everyone who clones a repository, commit this `.mcp.json` at the repository root instead:

```json .mcp.json
{
  "mcpServers": {
    "graphify": {
      "type": "http",
      "url": "https://api.graphify.com/mcp"
    }
  }
}
```

Each teammate approves the project server once, then signs in from `/mcp`.

### No `claude` command? Edit the config file

The Claude desktop app's **Code** tab and the IDE extensions run their own copy of Claude Code, so a terminal may answer `command not found: claude`. You don't need to install the CLI. The desktop app and the CLI read the same `~/.claude.json`, so add the server there:

1. Quit the desktop app or close the Claude Code session.
2. Back up the file: `cp ~/.claude.json ~/.claude.json.bak`.
3. Add `graphify` under the top-level `mcpServers` key. Create the key if it is missing, and leave every other key as it is:

```json ~/.claude.json
{
  "mcpServers": {
    "graphify": { "type": "http", "url": "https://api.graphify.com/mcp" }
  }
}
```

An entry at the top level is user scope, the same as `--scope user`. Keep `"type": "http"`: without it, Claude Code treats the entry as a local command and skips it.

Claude Code loads servers only when a session starts, so open a **new** session before you sign in.

## 2. Sign in

Adding the server does not sign you in. Until you do, Claude Code lists `graphify` as needing authentication and no tool call reaches Graphify.

<Steps>
  <Step title="Open the MCP panel">
    Start Claude Code and run `/mcp`.
  </Step>
  <Step title="Authenticate">
    Select **graphify** and choose **Authenticate**. Finish the sign-in in the browser window that opens, and pick the workspace that holds your repositories.
  </Step>
</Steps>

<Note>
If you don't have a Graphify account yet, you can create one while connecting. Finish workspace setup and enable a repository before you expect code answers.
</Note>

## 3. Check the connection

Run `claude mcp list` in a terminal. `graphify` should show **Connected**. Then paste this into Claude Code:

```text
Use Graphify's list_repositories tool and show the repositories I can access. If the tool fails, report the error instead of guessing.
```

This is the same test prompt the console shows on **Connectors → MCP → Try a query**. Check that the list matches the workspace you chose when you signed in.

### Optional: set a default repository

Add `?repo=owner/name` to the endpoint, for example `https://api.graphify.com/mcp?repo=Graphify-Labs/graphify`. Graphify uses that repository when a tool call names none. A repository named in the call still wins.

## 4. Ask a question

Pick a repository from the list and name the symbol, file, or area you care about:

- `Who calls the function that validates a session token?`
- `What would break if I changed this module's public interface?`
- `Summarize how requests reach the billing service.`

Answers are graph evidence from the files Graphify indexed, not a verified result. Open the source lines an answer cites before you rely on it. Some tools write workspace memory, so read each tool request before you approve it.

## Troubleshooting

| What you see | What to do |
| --- | --- |
| `graphify` shows **Needs authentication** | Run `/mcp`, select **graphify**, and choose **Authenticate**. |
| `command not found: claude` | You are in the desktop app or an IDE extension. Add the entry to `~/.claude.json` as in [No `claude` command?](#no-claude-command-edit-the-config-file), then start a new session. |
| Graphify works in one project but not another | You added it at local scope. Run the add command again with `--scope user`. |
| **Pending approval** next to `graphify` | It comes from a project `.mcp.json`. Start `claude` in that repository and approve it. |
| The tools return no repositories | The repository is not indexed yet, or it is in a different workspace. Check [Repositories and builds](/platform/repositories). |
| Every Graphify tool appears twice | You have both a user-scope entry and a project `.mcp.json` entry. Remove one with `claude mcp remove graphify`. |
| A Claude chat doesn't use Graphify | Select **+**, then **Connectors**, and turn Graphify on for that chat. Approve the tool call if Claude asks. |
| `/mcp` doesn't list the claude.ai connector | Run `/status`. Connectors from claude.ai load only with a Claude account login, not with `ANTHROPIC_API_KEY`, Bedrock, or another provider. Use `claude mcp add`, or `/login` with your Claude account. |
| The claude.ai connector is hidden | A local entry points at the same URL. Claude Code keeps the local entry. Remove it with `claude mcp remove graphify` if you want the directory connector. |
| Only a `graphify_setup` tool appears, or tools say **Graphify isn't set up for this account yet** | Finish setup at [app.graphify.com/onboarding](https://app.graphify.com/onboarding): create a workspace, connect GitHub, enable a repository, wait until it is **Indexed**, then start a new Claude Code session. If tools still fail, disconnect and reconnect Graphify under `/mcp`. |
| Tools say **This workspace has no repositories enabled for agents yet.** | Enable a repository under **Repositories** in Graphify, wait for the first index to finish, then ask again. |

## FAQ

### Do I need an API key to connect Claude to Graphify?

No. The directory connector and `claude mcp add` both sign in with OAuth in your browser. There is no key to paste or store. An `ANTHROPIC_API_KEY` login is a Claude Code credential. It does not replace Graphify sign-in, and it does not load connectors from claude.ai.

### Does Graphify read my local files from Claude Code?

No. The hosted server answers from repositories already indexed in your Graphify workspace. To build a graph from files on your machine instead, use the open-source package and its local skill.

### Is the Graphify MCP server free?

The Free plan (up to 3 repositories) needs no card. Pro and Teams start with a 14-day trial, card required. See [Plans and pricing](/platform/support/pricing) for Pro and Teams.

### Can I use the hosted server and the local Graphify skill together in Claude Code?

Yes, but they answer from different graphs. The hosted server reads your indexed workspace. The local skill reads `graphify-out/` in the repository. Pick one per question so answers stay consistent.

## 1. Install and register

```bash
uv tool install graphifyy
graphify install --platform claude
```

The integration writes Claude instructions and PreToolUse hooks that suggest consulting the graph for codebase questions. Exact destinations depend on whether you use a personal or project installation; the installer reports the files it writes.

For a repository-local setup, run this from the project root:

```bash
graphify install --project --platform claude
```

## 2. Build the graph

Open your project in Claude Code. Select the Graphify skill and enter:

```text
/graphify .
```

The assistant runs the Graphify workflow and writes `graphify-out/`. Code extraction runs locally; semantic extraction can use your assistant’s model for documents and media.

## 3. Ask with context

After the graph is built, ask:

> Use Graphify to explain the authentication flow. Cite the source files and distinguish explicit relationships from inferred ones.

You can also query from a terminal:

```bash
graphify query "authentication flow"
```

## Keep it current

```bash
uv tool upgrade graphifyy
graphify install --platform claude
```

If the skill is missing, refresh the assistant and confirm that the registration was installed in the intended user or project scope. See [troubleshooting](/open-source/troubleshooting).
