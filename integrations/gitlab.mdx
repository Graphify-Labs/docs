Graphify connects to projects on GitLab.com. Self-managed GitLab instances are not supported. You authorize Graphify with GitLab, choose the projects to index, and Graphify keeps each graph current from the project's default branch.

## Connect projects

<Steps>
  <Step title="Open Connectors">
    Sign in to [Graphify](https://app.graphify.com) and open **Connectors**.
  </Step>
  <Step title="Authorize GitLab">
    Click **Connect** on the GitLab card and approve access on GitLab. Graphify asks for the `api` and `read_repository` scopes. If GitLab grants fewer, the connection stops with a missing-scope error.
  </Step>
  <Step title="Choose projects">
    Choose the projects to index. Each one builds its first graph. When its status is **Indexed**, your agents can query it.
  </Step>
</Steps>

## What the connection does

- **Indexing.** A push to the default branch starts an index of that commit. See [Repositories and builds](/platform/repositories).
- **Reviews.** Merge requests are reviewed against the indexed graph and the diff. Graphify posts an advisory commit status and one merge request note, which it updates rather than repeats. The status does not block merging. See [Pull request reviews](/platform/reviews).

Indexing uses a token limited to `read_repository`.

## If something fails

- **Missing scope.** Connect again and approve every scope GitLab shows.
- **Project not listed.** Check that your GitLab account can access the project, then connect again.
- **Self-managed GitLab.** Only GitLab.com is supported.
- **`gitlab_not_connected`.** The workspace has no GitLab connection. Connect again.
- **Push didn't index.** Only Push Hook and Merge Request Hook events on the default branch count. Branch deletions are ignored. A push over the repository's daily index allowance is accepted but not indexed.
- **`repository_empty`.** The project has no commits on its default branch. Push one.

See [Troubleshooting](/platform/support/troubleshooting#repository-connect-issues).
