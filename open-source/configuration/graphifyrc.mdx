`.graphifyrc` is a small, committed file that tells Graphify Local the things it can't work out on its own. Most repositories never need one. You add it when an extension means different languages in different projects, or when your graph is too big for the default HTML view.

<Note>
**Use `.graphifyrc` when** files land in the wrong language (a `.inc` parsed as Pascal instead of PHP, a `.m` as Objective-C instead of MATLAB), or when git hooks should write `graph.html` with a different node limit. For per-run settings, such as models and output paths, use [environment variables](/open-source/configuration/environment-variables).
</Note>

## How it works

Graphify reads `<root>/.graphifyrc` once per scan, where `<root>` is the folder you pass to `extract`, `update`, or `watch`. The format is deliberately plain:

- One `key=value` per line.
- `#` starts a comment.
- Blank lines are ignored.

There are two keys.

## Configure

<ParamField path="language.<ext>" type="string">
  Treat every file with extension `<ext>` as the named language for classification, extractor choice, and cross-file resolution. Write `<ext>` with or without its leading dot. The value is either a language name or an extension Graphify already understands, such as `.php` or `.ts`.
</ParamField>

<ParamField path="viz_node_limit" type="integer">
  Node limit baked into the git hooks that `graphify hook install` writes. Graphs larger than this skip `graph.html`. An explicit `GRAPHIFY_VIZ_NODE_LIMIT` on the command line still wins.
</ParamField>

### Language names you can use

| Name | Maps to |
| --- | --- |
| `php` | `.php` |
| `pascal`, `delphi`, `freepascal` | `.pas` |
| `sql` | `.sql` |
| `python` | `.py` |
| `javascript`, `js` | `.js` |
| `typescript`, `ts` | `.ts` |
| `c` | `.c` |
| `cpp`, `c++`, `cxx` | `.cpp` |
| `objc`, `objective-c` | `.mm` |
| `java`, `kotlin`, `scala`, `groovy` | `.java`, `.kt`, `.scala`, `.groovy` |
| `go`, `golang` | `.go` |
| `rust` | `.rs` |
| `ruby` | `.rb` |
| `csharp`, `c#` | `.cs` |
| `swift`, `lua`, `zig`, `elixir` | `.swift`, `.lua`, `.zig`, `.ex` |

Any extension Graphify supports works as a value too, for example `language.tpl=.ts`. If a value isn't valid, Graphify prints `[graphify] warning: ignoring .graphifyrc: ...` and skips the whole file, so a typo never half-applies.

## See it in action

```ini .graphifyrc
# Every .inc in this repository is PHP, not Pascal
language.inc=php

# Templates here are plain TypeScript
language.tpl=.ts

# Skip graph.html above 2000 nodes when hooks rebuild
viz_node_limit=2000
```

Run an extraction and Graphify confirms the override:

```bash
graphify extract . --code-only
```

```text
[graphify extract] AST extraction on 92 code files...
  language overrides (.graphifyrc): .inc -> .php
```

## What changes

- Files with an overridden extension are parsed by that language's extractor and resolved against the same language's symbols.
- Hooks you install **after** adding `viz_node_limit` export it before each rebuild. Re-run `graphify hook install` after changing it.
- Nothing else reads `.graphifyrc`. Model, output, and logging settings live in environment variables.

## Verify and troubleshoot

| Symptom | Fix |
| --- | --- |
| No `language overrides` line in the output | Check that `.graphifyrc` sits in the folder you passed to `extract`, not a subfolder. |
| Files still use the old language | Look for an `ignoring .graphifyrc` warning, fix the line, then run `graphify extract . --force` for a full re-scan. |
| The hooks ignore `viz_node_limit` | Re-run `graphify hook install` to rewrite the hooks. |

<AccordionGroup>
  <Accordion title="Should I commit .graphifyrc?">
    Yes. It describes the repository, not your machine, so everyone who builds the graph should get the same result.
  </Accordion>
  <Accordion title="Why isn't .h mapped to C++ automatically?">
    `.h` is C in some projects and C++ in others, and `.inc` can be PHP, Pascal, SQL, or assembly. There's no correct global default, so the repository declares it.
  </Accordion>
  <Accordion title="Can I exclude files here?">
    No. Use [`.graphifyignore`](/open-source/configuration/ignoring-files).
  </Accordion>
</AccordionGroup>
