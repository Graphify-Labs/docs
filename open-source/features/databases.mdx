The code that queries a table is only half the picture. Graphify Local can read your database schema and your Rust workspace's crate graph, so your agent sees tables, views, functions, foreign keys, and crate dependencies next to the code.

<Note>
**Use this when** you're changing a table or a shared crate and want to know what depends on it.
</Note>

## Sources

| Source | How | What you get |
| --- | --- | --- |
| `.sql` files in the repo | Parsed automatically | Tables, views, and functions defined in the files |
| A live PostgreSQL database | `graphify extract --postgres <DSN>` | Tables, views, functions, and foreign-key relationships |
| A Rust workspace | `graphify extract --cargo` | Crate-to-crate dependencies |

Columns are not represented as separate nodes.

## How PostgreSQL introspection works

<Steps>
  <Step title="Connect read-only">
    Graphify opens a `READ ONLY` serializable transaction. It never writes to your database.
  </Step>
  <Step title="Read the catalog">
    It lists tables, views, and routines from `information_schema`, skipping the system schemas.
  </Step>
  <Step title="Rebuild DDL">
    It reconstructs the schema as SQL and runs it through the same parser used for `.sql` files.
  </Step>
</Steps>

If the connection fails, the error message is trimmed so your DSN and password don't end up in logs.

## See it in action

```bash
pip install "graphifyy[postgres]"
graphify extract . --postgres "postgresql://readonly@localhost:5432/app"
```

Pass an empty DSN to use the standard `PGHOST`, `PGUSER`, `PGPASSWORD`, and `PGDATABASE` environment variables, which keeps the password out of your shell history:

```bash
export PGHOST=localhost PGUSER=readonly PGDATABASE=app
graphify extract . --postgres ""
```

For a Rust workspace:

```bash
graphify extract . --cargo
```

Then ask about it like any other node:

```bash
graphify explain "orders"
graphify path "orders" "checkout"
```

## Configure

<Tabs>
  <Tab title="Least privilege">
    Create a role that can read the catalog and nothing else. Graphify needs no access to table data.
  </Tab>
  <Tab title="CI">
    Store the DSN as a secret and pass it through `PG*` variables in your job. See [Headless extraction](/open-source/features/headless-extraction).
  </Tab>
</Tabs>

## Verify and troubleshoot

| Symptom | Fix |
| --- | --- |
| `psycopg is required for --postgres` | `pip install "graphifyy[postgres]"` |
| `could not connect to PostgreSQL` | Check host, port, and role. The full error is hidden to protect credentials; test with `psql` first. |
| Tables missing | Only non-system schemas the role can see are read. Grant usage on the schema. |
| No crate edges | Run from your Rust workspace, or a folder under it, so Graphify can find the root `Cargo.toml`. |

<AccordionGroup>
  <Accordion title="Which databases are supported?">
    PostgreSQL for live introspection. Any dialect the SQL parser understands works from `.sql` files.
  </Accordion>
  <Accordion title="Does Graphify read rows?">
    No. Only catalog metadata: names, definitions, and relationships.
  </Accordion>
</AccordionGroup>
