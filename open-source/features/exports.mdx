Build a graph first, then export the same saved relationships into the format you need.

| Command | Output |
| --- | --- |
| `graphify export html` | Interactive graph visualization. |
| `graphify export callflow-html` | Architecture and call-flow HTML. |
| `graphify export wiki` | Markdown wiki organized around graph communities. |
| `graphify export obsidian` | Obsidian-compatible notes and links. |
| `graphify export svg` | Static SVG graph; requires the `svg` extra. |
| `graphify export graphml` | GraphML for tools such as Gephi or yEd. |
| `graphify export neo4j` | Cypher for Neo4j. |
| `graphify export falkordb` | Cypher for FalkorDB. |

## Generate a call-flow view

```bash
graphify export callflow-html --max-sections 8
graphify export callflow-html --output docs/architecture.html
```

The exporter reads the graph and associated report/labels. Explicit output paths make it easier to include the result in an internal documentation workflow.

## Export another graph

```bash
graphify export graphml --graph ./shared/graph.json
```

## Write to an existing Obsidian vault

```bash
graphify export obsidian --dir /absolute/path/to/vault
```

Review generated content before syncing it to a shared vault. The exporter is designed to preserve your own notes and `.obsidian` configuration.

## Push to a graph database

Neo4j and FalkorDB exports support optional push connections. Install the matching extra, use the appropriate connection URL, and supply passwords through `NEO4J_PASSWORD` or `FALKORDB_PASSWORD` rather than putting secrets on the command line.

## Run every export on a real repository

These examples come from a code-only graph of the open-source [httpx](https://github.com/encode/httpx) repository, built with Graphify Local 0.9.97. Your counts will differ.

```text

$ graphify export wiki

$ graphify export graphml

$ graphify export neo4j

  Sections: 17  |  Mermaid diagrams: 16  |  Call tables: 15
$ graphify tree

```

## Outputs

| Command | Writes | Needs |
| --- | --- | --- |
| `export html` | `graph.html` | Nothing extra. `--node-limit` defaults to 5000. |
| `export callflow-html` | `<name>-callflow.html` | Nothing extra. |
| `export wiki` | `wiki/` with `index.md` | Nothing extra. |
| `export obsidian` | `obsidian/` vault and `graph.canvas` | Nothing extra. |
| `export svg` | `graph.svg` | The `svg` extra. |
| `export graphml` | `graph.graphml` | Nothing extra. |
| `export neo4j` / `falkordb` | `cypher.txt`, or a push with `--push URI` | The `neo4j` / `falkordb` extra to push. |
| `tree` | `GRAPH_TREE.html` | Nothing extra. |

To push to a database, set `NEO4J_PASSWORD` or `FALKORDB_PASSWORD` instead of passing `--password`, so the secret stays out of your shell history.

## Troubleshooting

**`ImportError: matplotlib not installed. Run: pip install matplotlib`.** SVG export needs the `svg` extra:

```bash
pip install "graphifyy[svg]"
```

**`warning: graphify-out/.graphify_analysis.json is stale (1883 node(s) recorded vs 2341 in graph.json)`.** The graph changed after the last clustering. The export still runs, rebuilding communities from `graph.json`. To refresh community data, run:

```bash
graphify cluster-only .
```

## Flags

| Command | Flags |
| --- | --- |
| `export html` | `--graph PATH`, `--labels PATH`, `--node-limit N` (default 5000), `--no-viz` |
| `export callflow-html` | `--graph PATH`, `--labels PATH`, `--report PATH`, `--sections PATH`, `--output HTML`, `--lang auto\|zh-CN\|en`, `--max-sections N`, `--diagram-scale N` |
| `export obsidian` | `--graph PATH`, `--labels PATH`, `--dir PATH` |
| `export wiki` / `svg` | `--graph PATH`, `--labels PATH` |
| `export graphml` | `--graph PATH` |
| `export neo4j` / `falkordb` | `--graph PATH`, `--push URI`, `--user U`, `--password P` |
| `tree` | `--graph PATH`, `--output HTML`, `--root PATH`, `--max-children N` (default 200), `--top-k-edges N` (default 0, off), `--label NAME` |

## FAQ

**Do exports call an LLM?** No. They read `graph.json` and the label files.

**Which export should an agent read?** `wiki/index.md` is marked as the agent entry point.
