`graphify extract` runs the pipeline without an assistant skill. It is useful for repeatable local scripts and CI jobs.

## Code-only extraction

```bash
graphify extract . --code-only
```

This needs no model API key. Start here to verify installation and the project scope.

## Semantic extraction

Install the extra for your backend, configure its credentials outside the repository, then select it:

```bash
graphify extract ./docs --backend claude
```

Graphify supports Claude, Gemini, OpenAI, DeepSeek, Kimi, Ollama, Bedrock, Azure, and Claude CLI backends. [Configuration](/open-source/configuration/graphifyrc) maps backends to their environment variables. Do not assume a model supports every input type.

## Tune resource use

```bash
graphify extract ./docs --backend ollama --token-budget 4000 --max-concurrency 2
```

`--max-workers` controls structural extraction parallelism. `--max-concurrency` controls model requests. `--api-timeout` changes the request timeout. Smaller chunks and less concurrency can help a local model fit its available memory.

## CI pattern

Install a pinned package version in the CI environment, run extraction from the repository root, and retain the reviewed graph or report as an artifact. Use the same ignore rules and output location on every run. Supply provider credentials through the CI secret store only when semantic extraction is part of the job.

No provider key is necessary for `--code-only`. Do not make CI publication of the graph public unless the underlying source can be public too.

## Run it on a real repository

These examples come from a code-only graph of the open-source [httpx](https://github.com/encode/httpx) repository, built with Graphify CLI 0.9.97. Your counts will differ. A code-only run finished in about 2.6 seconds of wall time:

```text
$ time graphify extract . --code-only
[graphify extract] found 78 code, 0 docs, 0 papers, 0 images
[graphify extract] AST extraction on 78 code files...
  AST cache: 0/78 files served from cache (0%); 78 to extract
[graphify] Deduplicated 32 node(s) (28 exact, 4 fuzzy).
[graphify extract] wrote /workspace/runs/httpx/graphify-out/graph.json: 1883 nodes, 3960 edges, 106 communities
[graphify extract] next: run `graphify cluster-only /workspace/runs/httpx` to generate GRAPH_REPORT.md and name communities

real	0m2.601s
```

Follow it with `cluster-only` to write the report:

```text
$ graphify cluster-only . --no-label --no-viz
Graph: 1883 nodes, 3960 edges
Done - 106 communities. GRAPH_REPORT.md and graph.json updated (--no-viz; graph.html removed).
```

## Flags

| Flag | What it does |
| --- | --- |
| `--code-only` | Indexes code with local AST extraction and needs no API key. Skips documents, papers and images. |
| `--backend B` | `gemini`, `kimi`, `claude`, `openai`, `deepseek` or `ollama`. The default is whichever API key is set. |
| `--model M` | Overrides the backend's default model. |
| `--mode deep` | Extracts INFERRED semantic edges more aggressively. |
| `--force` | Re-scans everything and skips the semantic cache. You can also set `GRAPHIFY_FORCE=1`. |
| `--max-workers N` | The number of AST subprocesses. The default is the CPU count. |
| `--token-budget N` | The token cap per semantic chunk. The default is 60000. |
| `--max-concurrency N` | How many semantic chunks run at once. The default is 4; use 1 for local LLMs. |
| `--api-timeout S` | The per-request LLM timeout in seconds. The default is 600. |
| `--out DIR` | Writes `<DIR>/graphify-out/`. |
| `--no-gitignore` | Ignores `.gitignore`. `.graphifyignore` still applies. |
| `--no-cluster` | Writes the raw extraction only. |

For a self-hosted OpenAI-compatible server (llama.cpp, vLLM or LM Studio), use `--backend openai` and set `OPENAI_BASE_URL` and `OPENAI_MODEL`. For an Anthropic-compatible gateway, use `--backend claude` and set `ANTHROPIC_BASE_URL` and `ANTHROPIC_MODEL`.

## FAQ

**Why is `.netrc` skipped?** Credential files are never indexed. The run lists them as "skipped as potentially sensitive".

**Can CI fail when the graph shrinks?** `graph.json` reports the node count, so you can compare it in a script step. See the [incremental updates](/open-source/features/incremental-updates) page for `--force`.
