Real systems rarely live in one repository. A frontend calls an API, the API imports a shared client library, and a worker reads the same tables. Graphify Local can join separate graphs so your agent can follow a path from one repository into another.

There are two ways to do it:

| Approach | Use it for | Output |
| --- | --- | --- |
| `merge-graphs` | A fixed set of repositories, such as one product's services | A merged `graph.json` you choose the path for |
| `global` | Every project you work on, kept up to date over time | `~/.graphify/global-graph.json` |

<Note>
**Use this when** a change in one repository can break another, or when your agent keeps asking where a shared type is defined.
</Note>

## How it works

<Steps>
  <Step title="Build each repository">
    Run `graphify extract .` (or your usual build) in each repository so each has its own `graphify-out/graph.json`.
  </Step>
  <Step title="Combine">
    Nodes are tagged with their repository. Unresolved calls saved during each build are matched against definitions in the other repositories, so cross-repo member calls become real edges.
  </Step>
  <Step title="Re-cluster">
    The combined graph is clustered as a whole, so communities can span repositories.
  </Step>
</Steps>

## See it in action

<Tabs>
  <Tab title="merge-graphs">
    ```bash
    graphify merge-graphs ../web/graphify-out/graph.json ../api/graphify-out/graph.json \
      --out graphify-out/merged-graph.json
    graphify path "LoginForm" "create_session" --graph graphify-out/merged-graph.json
    ```
    The default output is `graphify-out/merged-graph.json`. Pass `--previous <path>` to keep the community IDs from an earlier merge.
  </Tab>
  <Tab title="global">
    ```bash
    graphify global add graphify-out/graph.json --as api
    graphify global list
    ```
    ```text
    Added 'api' to global graph: +3872 nodes, -0 pruned. Global: ~/.graphify/global-graph.json
    Global graph: ~/.graphify/global-graph.json
      api: 3872 nodes, added 2026-10-28
    ```
    Running `global add` again with the same tag replaces that repository's nodes. `--as` defaults to the parent folder's name.
  </Tab>
</Tabs>

Query the global graph by passing its path:

```bash
graphify query "where is the auth token validated" --graph "$(graphify global path)"
```

To pull in a public repository first, `graphify clone <github-url>` clones it locally and prints its path.

## Manage the global graph

| Command | Does |
| --- | --- |
| `graphify global add <graph.json> --as <tag>` | Add or update a repository |
| `graphify global remove <tag>` | Remove a repository's nodes |
| `graphify global list` | List repositories with node counts and dates |
| `graphify global path` | Print the global graph's location |

## Point your agent at it

The MCP server reads any graph file, so you can serve a merged graph:

```bash
graphify-mcp --graph graphify-out/merged-graph.json
```

See [MCP tools](/open-source/features/mcp-tools) for the tools it exposes.

## Verify and troubleshoot

| Symptom | Fix |
| --- | --- |
| No edges between repositories | Rebuild each repository with the current version so unresolved calls are saved, then merge again. |
| Duplicate nodes for a shared library | Build the library once and include its graph in the merge, instead of vendoring it. |
| Stale repository in the global graph | Run `global add` again with the same `--as` tag, or `global remove` it. |
| Community IDs change after each merge | Pass `--previous` with the last merged graph. |

<AccordionGroup>
  <Accordion title="Does merging change each repository's graph?">
    No. Inputs are read, not modified.
  </Accordion>
  <Accordion title="Is the global graph shared?">
    No. It's a file in your home folder.
  </Accordion>
</AccordionGroup>

## Run it on a second repository

These examples come from a code-only graph of the open-source [httpx](https://github.com/encode/httpx) repository, built with Graphify Local 0.9.97. Your counts will differ.

```text
$ graphify global add graphify-out/graph.json --as httpx
Added 'httpx' to global graph: +2315 nodes, -0 pruned. Global: /home/box/.graphify/global-graph.json
$ graphify global list
  httpx: 2315 nodes, added 2026-10-28
$ graphify global remove httpx
Removed 'httpx' from global graph (2278 nodes pruned).
```

To combine graphs into one file without the global graph, use `merge-graphs`:

```text
$ graphify merge-graphs a/graphify-out/graph.json b/graphify-out/graph.json --out merged.json
Merged 2 graphs -> 4629 nodes, 9082 edges
```

Pass `--previous <path>` to keep the earlier merged community IDs. Then a later `cluster-only` run can reuse the labels.

## Add a repository while you extract

`extract` can write a project graph and merge it into the global graph in one step:

```bash
graphify extract . --code-only --global --as sqldemo
graphify global path
```

```text
/home/box/.graphify/global-graph.json
```

`--as` sets the tag. Without it, the tag is the target directory's name. Use the same tag later to update or remove that repository:

```text
$ graphify global remove sqldemo
Removed 'sqldemo' from global graph (4 nodes pruned).
```

| Command | What it does |
| --- | --- |
| `global add <graph.json> [--as TAG]` | Adds or updates a project graph. |
| `global remove <tag>` | Removes that repository's nodes. |
| `global list` | Lists the repositories in the global graph. |
| `global path` | Prints the global graph's path. |
| `merge-graphs <g1> <g2> ... [--out PATH] [--previous PATH]` | Writes a merged file. The default is `graphify-out/merged-graph.json`. |

## FAQ

**Where is the global graph?** Run `graphify global path` to print it. By default it's `~/.graphify/global-graph.json`.
