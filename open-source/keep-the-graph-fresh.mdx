Your agent answers from the saved graph, not from the files on disk. **If the graph is old, the answers are old.** Open-source Graphify gives you two ways to refresh it without thinking about it: git hooks and a file watcher.

<Tip>
**Want this handled for you?** [Hosted Graphify](https://app.graphify.com?utm_source=docs&utm_medium=link&utm_campaign=open-source-keep-the-graph-fresh) rebuilds the graph on every push to your default branch, with nothing to install, and only re-processes the files that changed. See [how Graphify keeps your graph fresh](/platform/keep-the-graph-fresh).
</Tip>

## Pick a method

| Method | Refreshes when | Setup | Best for |
| --- | --- | --- | --- |
| **Git hooks** | You commit, switch branches, merge, pull or rebase | `graphify hook install`, once per repo | Most people |
| **graphify watch** | You save a code file | Keep a terminal open | Long editing sessions |
| **Hosted Graphify** | You push to GitHub | Connect the repo | Teams, with nothing to install |

## Git hooks

Run this once in each repository, after you've built a graph:

```bash
graphify hook install
graphify hook status
```

It adds four hooks and a merge driver for `graph.json`:

| Hook | Runs after | What it rebuilds |
| --- | --- | --- |
| `post-commit` | `git commit` | Only the files that commit changed |
| `post-checkout` | Switching branches | The whole code graph |
| `post-merge` | `git merge`, and `git pull` that merges | The whole code graph |
| `post-rewrite` | A rebase, including `git pull --rebase` | The whole code graph |

**You don't need to run `graphify update .` after `git pull`.** The `post-merge` or `post-rewrite` hook does it for you.

### What hook install changes in your repo

`graphify hook install` writes four hook files, one `.gitattributes` line, and two keys in the repository's git config. Nothing is written to the global git config.

By default the files are `.git/hooks/post-commit`, `.git/hooks/post-checkout`, `.git/hooks/post-merge`, and `.git/hooks/post-rewrite`. Each graphify block sits between its own start and end markers:

| Hook | Start marker | End marker |
| --- | --- | --- |
| `post-commit` | `# graphify-hook-start` | `# graphify-hook-end` |
| `post-checkout` | `# graphify-checkout-hook-start` | `# graphify-checkout-hook-end` |
| `post-merge` | `# graphify-merge-hook-start` | `# graphify-merge-hook-end` |
| `post-rewrite` | `# graphify-rewrite-hook-start` | `# graphify-rewrite-hook-end` |

If the hook file already exists, the block is added after the lines that are already there. Those lines stay. A new hook file starts with `#!/bin/sh` and is made executable.

If `core.hooksPath` is `.husky/_`, the four hook files are written to `.husky/`. A missing `.husky/_` directory is created as well. A `core.hooksPath` outside the repository is refused, and the files are written to `.git/hooks`.

It adds `graphify-out/graph.json merge=graphify` to `.gitattributes`. Every other line in that file stays.

In `.git/config` it sets:

- `merge.graphify.name` to `graphify graph.json union merge`
- `merge.graphify.driver` to the quoted path of the Python interpreter that ran `graphify hook install`, followed by `-m graphify merge-driver %O %A %B`

The hook scripts store that same interpreter path. After you move or reinstall that Python, the hooks and the merge driver still call the old path until you run `graphify hook install` again.

### Turn off or remove the hooks

Set `GRAPHIFY_SKIP_HOOK=1` for a single git command, for example `GRAPHIFY_SKIP_HOOK=1 git pull`. The rebuild is skipped for that command. The hooks stay installed.

`graphify hook uninstall` removes only the graphify marker block from each of the four hook files. Lines you added stay. The file is deleted when nothing is left, or when the only line left is `#!/bin/sh` or `#!/bin/bash`. It removes the `merge=graphify` line from `.gitattributes`, and deletes `.gitattributes` when that line was the only one. It unsets `merge.graphify.name` and `merge.graphify.driver` in the local git config.

`graphify uninstall` without `--project` removes those same hooks and the merge driver. `graphify-out/` stays. `graphify uninstall --purge` is what deletes it. The rebuild log at `~/.cache/graphify-rebuild.log` stays after either command, including `graphify uninstall --purge`.

### Check that it's working

`graphify hook status` should print:

```text
post-commit: installed
post-checkout: installed
post-merge: installed
post-rewrite: installed
merge driver: registered
```

If a line says `out of date`, run `graphify hook install` again. To see what a rebuild did, read `~/.cache/graphify-rebuild.log`.

A few things to know:

- **It runs in the background.** Git returns straight away, so a query right after a commit or pull can still see the old graph for a moment. Output goes to `~/.cache/graphify-rebuild.log`.
- **It needs a graph to exist.** Build one first with `/graphify .` or `graphify extract .`. The branch, merge and rebase hooks do nothing until `graphify-out/` exists.
- **It skips some moments on purpose.** No rebuild runs mid-rebase, in a linked `git worktree`, or when `GRAPHIFY_SKIP_HOOK=1` is set.
- **It keeps your own hooks.** Graphify adds its block between markers and leaves the rest of the file alone. See [What hook install changes in your repo](#what-hook-install-changes-in-your-repo).
- **Re-run it after moving Python.** The hooks and the merge driver keep the interpreter path from `hook install`. See [What hook install changes in your repo](#what-hook-install-changes-in-your-repo).

## graphify watch

The watcher needs the `watch` extra:

```bash
uv tool install "graphifyy[watch]"
graphify watch .
```

It waits until files stop changing for three seconds, then:

- **Code changed:** rebuilds the code graph right away. No model is called.
- **A doc, PDF or image changed:** writes a `graphify-out/needs_update` flag and tells you to run `/graphify --update` in your assistant. It does not call a model by itself.
- **A file was deleted:** rebuilds, so the deleted file's nodes drop out.

Stop it with **Ctrl+C**. The watcher only runs while that terminal is open, so hooks are the better default.

## What stays manual

Hooks and the watcher refresh **code**. They never call a model, so changes to docs, PDFs and images wait for you:

```text
/graphify . --update
```

Run `graphify check-update .` to see whether a doc refresh is pending.

## Known limits

These are open issues in the Graphify CLI repository. We'll update this page when they're fixed.

<AccordionGroup>
  <Accordion title="Hooks rebuild a --code-only graph as a full graph">
    If you built with `graphify extract . --code-only`, the next branch switch, merge or rebase rebuilds it with docs included, so it grows. The rebuild doesn't remember the scope you chose. Until this is fixed, add docs you want kept out to `.graphifyignore`. Tracked in [#4923](https://github.com/Graphify-Labs/graphify/issues/4923).
  </Accordion>
  <Accordion title="Deleting a doc can re-queue every other doc">
    After you delete a document and run `/graphify --update`, the next update can treat all your other docs as changed and run them through the semantic pass again. Cached results still save the model calls, but the run takes longer. Tracked in [#4914](https://github.com/Graphify-Labs/graphify/issues/4914).
  </Accordion>
  <Accordion title="An interrupted doc extraction can look finished">
    If you stop a semantic extraction partway through a long document, the cache can mark that document as done, and later updates skip the part that never ran. If you interrupted a run, rebuild that file with `graphify extract . --force`. Tracked in [#4943](https://github.com/Graphify-Labs/graphify/issues/4943).
  </Accordion>
</AccordionGroup>

## FAQ

<AccordionGroup>
  <Accordion title="How do I keep a code graph up to date automatically?">
    Run `graphify hook install` once in the repository. From then on, git rebuilds the code graph after each commit, branch switch, merge, pull and rebase. With [hosted Graphify](https://app.graphify.com?utm_source=docs&utm_medium=link&utm_campaign=open-source-keep-the-graph-fresh), the graph rebuilds on every push and there's nothing to install.
  </Accordion>
  <Accordion title="Do I still need graphify update after git pull?">
    Not if you've run `graphify hook install`. A pull that merges fires `post-merge`, and `git pull --rebase` fires `post-rewrite`. Both rebuild the code graph in the background. Without hooks, run `graphify update .` yourself.
  </Accordion>
  <Accordion title="Should I use hooks and watch together?">
    You can. Rebuilds take a per-repository lock and queue behind each other, so they don't pile up. Most people only need hooks.
  </Accordion>
  <Accordion title="How do I turn the hooks off for one command?">
    Set `GRAPHIFY_SKIP_HOOK=1`, for example `GRAPHIFY_SKIP_HOOK=1 git pull`. To remove the hooks, see [Turn off or remove the hooks](#turn-off-or-remove-the-hooks).
  </Accordion>
  <Accordion title="Do the hooks call a model or use tokens?">
    No. Hooks and the watcher only re-read code, locally. Docs, PDFs and images refresh when you run `/graphify . --update`.
  </Accordion>
</AccordionGroup>
