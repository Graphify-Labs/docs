The Graphify Local repository ships a `Dockerfile` that runs `graphify-mcp` over streamable HTTP. Mount a `graphify-out/` folder into the container and every agent on your network can query the same graph.

<Note>
**Self-host when** your team wants one shared graph but the code must stay on your own infrastructure. If you don't want to run a server, [Graphify](/integrations/other-agents) hosts the MCP endpoint for you.
</Note>

## How the image works

The image is built from [`Dockerfile`](https://github.com/Graphify-Labs/graphify/blob/HEAD/Dockerfile) in the repository root:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY . /app
RUN pip install --no-cache-dir ".[mcp]"
RUN useradd --create-home --uid 10001 graphify
USER graphify
EXPOSE 8080
ENTRYPOINT ["python", "-m", "graphify.serve"]
CMD ["/data/graph.json", "--transport", "http", "--host", "0.0.0.0", "--port", "8080"]
```

- It installs only the `mcp` extra, so the image serves graphs but doesn't build them.
- It runs as a non-root user (UID `10001`).
- The default command reads `/data/graph.json`, so you mount your `graphify-out/` folder at `/data`.

Graphify doesn't publish a prebuilt image, so you build it yourself.

## Run it

<Steps>
  <Step title="Build a graph">
    On a machine with Graphify Local installed:

    ```bash
    graphify extract . --code-only
    ```
  </Step>
  <Step title="Build the image">
    ```bash
    git clone https://github.com/Graphify-Labs/graphify.git
    cd graphify
    docker build -t graphify .
    ```
  </Step>
  <Step title="Start the server with a key">
    ```bash
    export GRAPHIFY_API_KEY="$(openssl rand -hex 32)"

    docker run -d --name graphify-mcp -p 127.0.0.1:8080:8080 \
      -v "/path/to/repo/graphify-out:/data:ro" \
      graphify /data/graph.json --transport http --host 0.0.0.0 --api-key "$GRAPHIFY_API_KEY"
    ```

    Arguments after the image name replace the default command, so repeat the graph path and transport flags when you add `--api-key`.
  </Step>
  <Step title="Point clients at it">
    For clients that take a URL and headers, such as Cursor:

    ```json
    {
      "mcpServers": {
        "graphify": {
          "url": "http://your-host:8080/mcp",
          "headers": { "Authorization": "Bearer <your key>" }
        }
      }
    }
    ```

    Clients can also send the key as an `X-API-Key` header.
  </Step>
</Steps>

<Warning>
Always set `--api-key` when you bind `0.0.0.0`. Without one, anyone who can reach the port can read your graph, and the server logs a warning at start-up. Put the server behind TLS (a reverse proxy or load balancer) before exposing it beyond a private network.
</Warning>

## Configure

| Flag | Default | When to change it |
| --- | --- | --- |
| `--api-key` | `GRAPHIFY_API_KEY` env | Always, for any shared server |
| `--port` | `8080` | Another service already uses 8080 |
| `--path` | `/mcp` | Your proxy routes a different path |
| `--stateless` | off | You run several replicas behind a load balancer |
| `--json-response` | off | Your client can't read server-sent events |
| `--session-timeout` | `3600` | Long-idle agents lose their session; `0` disables the timeout |

## Keep the graph fresh

The server reloads `graph.json` whenever the file changes, so you don't restart the container. Rebuild the graph on the host and the mounted file updates in place:

```bash
graphify update /path/to/repo
```

To automate this, run `graphify hook install` in the repository on the host that owns the mount, or run `graphify update` from a scheduled CI job that writes to the same volume.

## Verify and troubleshoot

```bash
docker logs graphify-mcp
```

Look for `graphify MCP server (streamable-http) on http://0.0.0.0:8080/mcp - api-key required`. Then send an `initialize` request with your key, as shown in the [MCP server quickstart](/open-source/mcp-server#verify-the-connection). A `200` means it works; `401` means the key is missing or wrong.

<AccordionGroup>
  <Accordion title="The container exits straight away">
    The graph path doesn't exist inside the container. Check that the mount points at a folder containing `graph.json` and that UID `10001` can read it.
  </Accordion>
  <Accordion title="Can the container build graphs too?">
    Not as shipped. It installs only the `mcp` extra. Build graphs on the host or in CI, and use the container to serve them.
  </Accordion>
  <Accordion title="Can I serve several repositories?">
    Run one container per graph, or merge repositories into one graph first with `graphify merge-graphs`.
  </Accordion>
</AccordionGroup>
