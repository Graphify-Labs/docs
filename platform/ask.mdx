**Ask** is where you question a repository in plain language. Graphify answers from the code knowledge graph of that repository, not from a model's guess: every answer cites the nodes it used and the path it followed. When the graph has no path that answers your question, Ask tells you it found no answer instead of inventing one.

<Note>
**Use Ask when** you want to know who owns some behavior, how two parts of the code connect, or where something actually lives, before you open an editor.
</Note>

## Before you start

- A Graphify account at [app.graphify.com](https://app.graphify.com).
- At least one repository with the status **Indexed**. See [Index a repository](/concepts/index-a-repository).

## How it works

<Steps>
  <Step title="Pick a repository">
    Open **Ask** in the Console and choose the repository to query.
  </Step>
  <Step title="Ask a question">
    Type a question about ownership, call paths, or where behavior lives. While it works, Ask shows **Tracing the graph**.
  </Step>
  <Step title="Read the grounded answer">
    The answer is a short explanation plus the graph nodes it cites. **Traced through** lists the path it followed, so you can check every step.
  </Step>
  <Step title="Go deeper">
    Select **Open the graph** to see the cited nodes in [Graph explorer](/platform/graphs).
  </Step>
</Steps>

## Two modes

<Tabs>
  <Tab title="Ask">
    Questions and grounded answers. Good starters:

    - "Where is the session token validated?"
    - "What calls `create_invoice`?"
    - "How does the upload worker reach the storage client?"
  </Tab>
  <Tab title="Plan a change">
    Select **Plan a change**, then describe what should work differently. For example: *let users retry a failed upload without selecting the file again.* If you know where to start, add a **File or function**.

    Graphify finds the relevant code and suggests a plan with source links. It won't edit your code.
  </Tab>
</Tabs>

## What Ask detects in a question

- **Pull request questions.** Mention `#1234`, `PR 1234`, or a pull request URL. Ask answers from that pull request's completed review.
- **Task descriptions.** Paste a task, such as a ticket body. Ask returns guidance on where the change goes.
- **Code questions.** Everything else. Ask searches the graph and cites the nodes it used.

Each answer has prose, citations, and graph paths. When no grounded path exists, the answer abstains. That's a normal answer, not an error.

## Link straight to a question

Ask reads the URL, so you can share a question or open a mode directly:

| URL | Opens |
| --- | --- |
| `/<workspace>/ask?q=where%20is%20auth%20handled` | Ask, with the question already submitted |
| `/<workspace>/ask?mode=change` | Ask, with **Plan a change** open |

## When Ask has no answer

**No answer found for this question** means the graph has no path that supports an answer. This is deliberate: a near-miss is reported as no answer rather than a confident guess. To get an answer:

- Name a real symbol, file, or module.
- Ask about one relationship at a time.
- Check the repository finished indexing. If Ask says it **isn't connected to your code yet**, the repository has no graph.

## An example answer

The Console's demo preview uses a sample graph to show what an answer looks like. Asked "where is retry handled?", it answers:

> Retry is handled in the workers module. retry_with_backoff in workers/dispatch.py is the shared helper: dispatch_job calls it directly, an extracted relationship, and billing's retry_charge (billing/invoices.py) appears to reach it as well, though that edge is inferred from usage rather than parsed.

The answer cites each node with its file and confidence tag:

| Node | File | Confidence |
| --- | --- | --- |
| `retry_with_backoff` | `workers/dispatch.py` | extracted |
| `dispatch_job` | `workers/dispatch.py` | extracted |
| `retry_charge` | `billing/invoices.py` | extracted |
| `requeue_stale` | `workers/queue.py` | inferred |

**Traced through** lists each step, such as `dispatch_job` → calls → `retry_with_backoff`. When a step is inferred, the answer says so, for example "treat it as probably right, not proven." The demo data is a sample graph, not your code.

## Ask from anywhere

You don't have to open the Ask page. The Ask bar in the Console reads **Deep research your codebase...**. Select it, or press <kbd>⌘</kbd>+<kbd>I</kbd> on macOS or <kbd>Ctrl</kbd>+<kbd>I</kbd> on Windows and Linux, to ask without leaving the page you're on.

When the box is empty, Ask may show up to four questions under **Suggested from your repository**. They're drawn from that repository. Select one to ask it.

## Limits

- Each question goes to one repository. To compare repositories, ask each one, or use a [combined graph](/platform/graphs).
- Your workspace can send 30 Ask requests a minute. Over that returns `429 rate_limited`. Wait a minute and ask again.
- Ask needs an active plan. The Free plan (up to 3 repositories) needs no card. Pro and Teams start with a 14-day trial, card required.

## Verify and troubleshoot

| Symptom | Fix |
| --- | --- |
| No repositories to pick | Connect and index a repository from **Repositories**. |
| Every question has no answer | Indexing may still be running. Wait for **Indexed**. |
| Answer cites the wrong module | Open the cited node in the graph and refine the question with the correct name. |
| "A question is required." | The box was empty. Type a question. |
| "This organization's subscription is inactive." | Your workspace plan isn't active. Check **Billing**. |
| "Ask is not available yet." (`ask_unavailable`) | Ask isn't turned on for this environment. Try again later. |
| "Too many requests. Please slow down." | Over 30 a minute. See [Troubleshooting](/platform/support/troubleshooting#429-rate-limited-too-many-requests-please-slow-down). |

<AccordionGroup>
  <Accordion title="Does Ask change my code?">
    No. Both modes only read the graph. **Plan a change** produces a plan with links, not edits.
  </Accordion>
  <Accordion title="Can my coding agent ask the same questions?">
    Yes. Connect it to the [hosted MCP](/platform/hosted-mcp) and it queries the same graph.
  </Accordion>
  <Accordion title="Why does Ask answer each question on its own?">
    Ask doesn't carry hidden assumptions between questions. Name the symbol or module again in a follow-up so the graph search starts from the right place.
  </Accordion>
  <Accordion title="Can Ask be wrong?">
    Yes. Inferred steps are labelled, and every claim links to the code. Open the cited node and check it before you act on it.
  </Accordion>
</AccordionGroup>
