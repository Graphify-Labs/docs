**Memory** holds your repository's decisions, incidents, and lessons as your coding agents record them, with evidence and history for your team and your agents. Facts are consolidated per code entity, not per conversation, so when an agent edits a function, it recalls what's known about that function.

<Note>
**Use Memory when** you want to know why something is the way it is, what an agent learned in an earlier session, or which facts are tied to code that still exists.
</Note>

## Before you start

- A Graphify account at [app.graphify.com](https://app.graphify.com).
- An indexed repository.
- A coding agent connected through the [hosted MCP](/platform/hosted-mcp). Memories are written by agents, so a new repository has none.

## How it works

<Steps>
  <Step title="Agents record">
    Connected agents write memories over MCP or the HTTP endpoint. Memories are scoped to your workspace.
  </Step>
  <Step title="Distil">
    A model turns raw memories into candidate facts.
  </Step>
  <Step title="Merge by rule">
    Duplicates fold by rule, never by model, so merging is deterministic.
  </Step>
  <Step title="Anchor">
    Each fact is anchored to the code entity it describes when one resolves. Provenance and anchors survive merging.
  </Step>
</Steps>

## Explore memory

<Steps>
  <Step title="Open Memory">
    Open **Memory** in the Console and choose a **Repository**.
  </Step>
  <Step title="Recall">
    Use **Recall a fact, entity, or anchor** to search, or pick from **Memory entities**.
  </Step>
  <Step title="Inspect a fact">
    Read the **Remembered facts** for an entity, with their source turns and the graph node they're anchored to.
  </Step>
</Steps>

The **Memory summary** shows **Entities covered**, how many facts are **Grounded**, and **Tokens saved**.

## Grounded and ungrounded facts

A fact is **grounded** when it's anchored to a code node that still resolves. Ungrounded facts are normal, not errors: a decision about process, or about code since deleted, has nothing to anchor to.

A remembered fact and an extracted code relationship are different kinds of evidence. For the current behavior, follow the anchor to [Graph explorer](/platform/graphs) and read the code. Explicit instructions and human decisions take precedence over anything inferred.

## How Memory fits with your agent's own memory

Your agent can keep its own preferences and session notes. Graphify adds shared knowledge tied to your repositories that other agents and teammates in the workspace can inspect. Graphify doesn't sync with or replace another memory store.

## Add a memory

<Steps>
  <Step title="Write it">
    Write one fact your team should keep. For example: *Retry failed card charges at most three times, and never retry hard declines.*
  </Step>
  <Step title="Give it a topic">
    Add a short topic, such as *Payment retry policy*, so related memories stay together. Graphify suggests one from your text, and you can change it.
  </Step>
  <Step title="Save">
    Select **Save and keep**. The Console shows **Kept. Graphify is processing it.** Memories are attributed to you. Your GitHub files aren't changed.
  </Step>
</Steps>

## Suggestions and kept memories

Graphify also picks up memories from recent conversations and from AI agents. These start as suggestions. Ask only uses a suggestion after someone keeps it. Connected agents may already see it, marked as unverified.

| Label | Meaning |
| --- | --- |
| **Added automatically, not reviewed** | An agent or recent activity added it, and nobody has reviewed it. |
| **Saved by an AI agent** | A connected agent saved it. |
| **From a conversation** | It came from an Ask or agent conversation. |

Keep a suggestion as it is, edit it and keep it, or discard it. If the code a memory refers to changes after it was saved, the memory is flagged: "The code this refers to changed after it was saved. Check that it is still true." When two current versions disagree, Ask and agents use neither until you edit one to say which is right.

## Remove and restore

Removing a memory means Ask and agents stop using it. Its history is kept, and you can restore it.

## Ask what your team knows

Search memory with plain words to find saved decisions, incidents and lessons. Turn on **Only linked to code** to see only memories anchored to code, or turn on **Include suggestions not yet kept** or **Include what was said in conversations** to search more widely. Ask answers each question on its own, so name what you mean in follow-ups.

## Verify and troubleshoot

| Symptom | Fix |
| --- | --- |
| Memory is empty | Select **Connect an agent** and connect one over MCP. |
| **Source turns are unavailable** | The original conversation turns can't be loaded. The fact and its anchor remain. |
| Many facts ungrounded | Expected for process decisions. For code facts, check the code still exists. |
| **No saved memories match that.** | Try fewer words, or include suggestions in the options. |
| **Memories will be available once indexing finishes.** | Wait for the repository to finish indexing. |
| **Indexing failed, so answers may be incomplete.** | Re-index the repository from **Repositories**. |
| **Ask isn't available right now.** | Memory still lists saved memories that match your question. Try Ask again later. |
