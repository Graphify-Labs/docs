One shared context for your coding agents and your team. Graphify maps your repositories into a code graph, keeps your team's decisions, incidents and lessons in Memory, writes a Wiki in the Graphify app, and reviews your pull requests across repositories with the same graph.

Your agents query it through one hosted MCP server, and your team reads the same context at [app.graphify.com](https://app.graphify.com?utm_source=docs&utm_medium=link&utm_campaign=platform-overview). We run it for you, so there's nothing to deploy. Your work lives in a workspace: a personal one for you, or a team workspace you share.

## Why teams use Graphify

- One context for every agent. Claude Code, Codex, Cursor and other MCP clients query the same code graph and Memory through `https://api.graphify.com/mcp`. They sign in with OAuth, so there's no API key to paste.
- Incident memory that outlives the session. Decisions, incidents and lessons are tied to the files and functions they describe, so the next agent can recall them before it edits that file or function.
- Reviews that see past the diff. Graphify reviews each pull request with the graph, including what the change reaches in the other repositories of a cross-repository graph.
- Context that stays current. Every push to the default branch rebuilds the graph, and your agents keep using the previous one until the new build is ready.

## How it works

<HowItWorksDiagram />

Graphify turns your repositories into one code graph. Memory, the Wiki and PR reviews all build on that graph, so your agents and your team work from the same context.

<Steps>
  <Step title="Connect your repositories">
    Install the Graphify GitHub App, or connect GitLab, and choose the repositories Graphify can read.
  </Step>
  <Step title="Graphify builds the code graph">
    It indexes the default branch into a graph of files, symbols, calls and imports, and rebuilds it on every push.
  </Step>
  <Step title="Your agents query it over MCP">
    Coding agents ask the graph who calls a function, what a change could break, and what your team remembers about that code.
  </Step>
  <Step title="Your team's context grows">
    Reviews, the Wiki and Memory build on the same graph, and replies on reviews teach Graphify what your team cares about.
  </Step>
</Steps>

## First steps in the Graphify app

<Steps>
  <Step titleSize="h2" title="Open your workspace">
    Go to [app.graphify.com](https://app.graphify.com?utm_source=docs&utm_medium=link&utm_campaign=platform-overview). Sign in with Google, GitHub, GitLab, or email. If you are new to Graphify, select **Create an account** from the login page. On the login page, **Forgot your password?** starts a reset. That link is on login, not on signup.
  </Step>
  <Step titleSize="h2" title="Connect a repository">
    Follow the repository setup in your workspace. Graphify builds a graph of the repositories you connect. Use **Overview** to see your graphs, indexing status, and recent builds.
  </Step>
  <Step titleSize="h2" title="Explore the relationships">
    Open a graph to inspect its nodes and connections. Use the cross-repository view when you need context across services and shared code. The [Graphify app tour](/platform/console) walks through the product screens.
  </Step>
  <Step titleSize="h2" title="Connect your coding agent">
    Use **Connect agent** in the Graphify app, or follow the [client-specific MCP instructions](https://graphify.com/mcp?utm_source=docs&utm_medium=link&utm_campaign=platform-overview). The hosted connection uses an OAuth sign-in so your assistant can access your Graphify workspace.
  </Step>
  <Step titleSize="h2" title="Get a review on your next pull request">
    **PR reviews** is on for a connected repository unless someone turns it off. Open a pull request, or mark a draft ready for review, and Graphify reviews it with the graph. On GitHub, the review shows up as a review comment and a **Graphify** check run. See [Review a pull request](/platform/reviews/review-a-pull-request).
  </Step>
</Steps>

## Graphify and Graphify CLI

Graphify manages the hosted workspace for your connected repositories. The [open-source quickstart](/open-source/quickstart) runs the graph engine on your machine and writes the output into your project. Its CLI commands and local MCP setup are documented separately in these docs. To compare the two side by side, see [Graphify vs Graphify CLI](/platform/graphify-vs-local). To move a repository, follow [Move from Graphify CLI](/platform/support/move-from-local).

Formal verification is part of Graphify. Available features, permissions, and usage limits depend on your workspace and plan; see [plans and pricing](/platform/support/pricing) for hosted allowances.

For self-hosting, SSO/SAML, GitHub Enterprise, and procurement requirements, see [Enterprise](/platform/support/pricing#enterprise).

## Start with your goal

For workspaces in the personalized-discovery rollout, workspace creation includes one optional question: **What would you like to do first?** You can choose agent-assisted development, understanding code, reviewing changes, sharing knowledge, product integration, or exploring Graphify. Leaving it blank keeps a balanced introduction.

**Overview → Explore Graphify** explains available capabilities and opens their destinations. Your goal changes recommendation emphasis; it keeps the sidebar and feature access stable. **Settings → Your experience** lets you change your goal, optionally add a work role, or choose **Only when I ask** to suppress unsolicited suggestions and automatic tours. Preferences are personal to you in each workspace.

Structure and pattern discovery are rolling out separately and require a compatible index. Missing coverage is shown explicitly. Graphify and open-source Graphify can expose different capabilities; follow what your setup shows.
