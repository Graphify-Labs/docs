**Two signals, two questions.** A review finding is a concern to investigate. A verification verdict says what was proved. Read both before you call a pull request safe.

<CardGroup cols={2}>
  <Card title="Investigate a review finding" icon="message-square-warning">
    Open **Reviews**, pick the repository and run, and check the commit. Findings are advisory and describe that revision. With repository settings on, you also see **Risky patterns (advisory)** and **Docs that may be stale (advisory)**.
  </Card>
  <Card title="Check a verification verdict" icon="shield-check">
    Open **Formal Verification** and expand the run. The run status says if processing finished. Each function's result says what was established.
  </Card>
</CardGroup>

## Read the verdict

| Result | GitHub / API | Means |
| --- | --- | --- |
| **≠ Behavior changed** | Behavior change / `distinguished` | Different results on the same input. Check if it was reproduced or is unconfirmed. |
| **= Proven same** | Proved equivalent / `equivalent` | Same result for every input in the range checked. |
| **≈ No change found** | No divergence sampled / `may_equivalent` | Same on every input tried. Evidence, not proof. |
| **? Not checked** | Abstained / `unsupported` | Couldn't compare. Tells you nothing. |
| **! Couldn't run** | Errored / `error` | The check failed. Says nothing about your code. |

<Note>
**Completed** is the run's lifecycle status. It doesn't mean every function was Proven same. A run can mix results.
</Note>
