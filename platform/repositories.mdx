**Repositories** controls which codebases Graphify indexes. **Builds** shows the indexing runs that produce their graphs and wiki content.

## Connect a repository

Open **Repositories** in [Graphify](https://app.graphify.com). Click **Add GitHub repositories**, or click **Connect** on the GitLab card in **Connectors**, then complete the provider's repository-access flow. Google Drive folders are added from **Connectors**. Follow [Connect Google Drive](/integrations/google-drive).

Return to the repository list to check indexing status. Provider and status filters help narrow a large workspace.

| Status | Meaning |
| --- | --- |
| **Indexed** | A graph has been built and is available. |
| **Building** | Indexing is running. |
| **Queued** | The repository is waiting to build. |
| **Failed** | The latest attempt did not finish successfully. |
| **Paused** | Indexing is disabled for the repository. |

## Repository controls

Open a repository's options to inspect available controls for **PR reviews**, **Fix suggestions**, **Formal verification**, and **Indexing**. Available actions depend on the workspace's configuration and access.

The Indexing control pauses or enables indexing. Review and verification controls are separate; do not use an indexing toggle as a substitute for review configuration.

## When a repository is indexed

A push to the repository's default branch starts an index of that commit. On GitHub and GitLab, the default branch is the branch the provider marks as default, often `main`.

A push to any other branch does not update the graph. Branches named `dev` or `uat` are not indexed unless one of them is the default branch. A pull request does not build a second graph. Graphify keeps one graph per repository, and that graph is the default branch. A pull request is reviewed against that graph and the pull request's diff. See [Pull request reviews](/platform/reviews).

There is no setting to index every branch, or to index on every pull request. To index a different line of development, make that branch the default branch on GitHub or GitLab. **Retry** on a failed build indexes the current head of the default branch.

One index of a repository runs at a time. A later push to the default branch waits, or joins the build already queued. Hosted plans can also limit how many push-triggered indexes a repository finishes in a UTC day. A manual reindex does not use that allowance. The allowances are on [plans and pricing](/platform/support/pricing). The repository row can show **Out of date** when the newest default-branch commit is not the commit the graph is serving, and no build for that commit is running.

## Follow a build

Open **Builds** and filter by repository or status. A build row identifies the repository, run state, and available timing or graph information.

- For a queued or running build, use the available cancel control if you need to stop that attempt.
- For a failed build, **Retry** starts indexing the repository's current head. It does not replay the historical failed commit.
- If no rows match, clear the filters before concluding that the repository has never built.

The first completed index makes code context available in [Graphs](/platform/graphs). [Wiki](/platform/wiki) is generated alongside the code graph when available for the workspace.

## Build states

| State | Meaning |
| --- | --- |
| `queued` | Waiting for a worker. A later push joins this build. |
| `provisioning` | Graphify is preparing the indexing environment. |
| `indexing` | The default-branch commit is being parsed into the graph. |
| `promoting` | The new graph is replacing the one being served. |
| `ready` | The graph for this commit is live. |
| `failed` | The build stopped. The previous graph keeps serving. Use **Retry**. |
| `cancelled` | Someone cancelled the build. |

## Sync and reindex

**Sync** refreshes the list of repositories your GitHub or GitLab connection can see. **Reindex** rebuilds one repository's graph from its default-branch head. You need permission to manage repositories in the workspace.

These events never start an index: a push to a non-default branch, a branch deletion, and any push to a repository whose indexing is off.

| Code | Status | What it means |
| --- | --- | --- |
| `repository_disabled` | 409 | "Enable the repository before re-indexing." Turn **Indexing** back on. |
| `index_rebuild_debounced` | 409 | A rebuild was requested moments ago. The response includes `retryAfterSeconds`. Wait that long. |
| `provider_disconnected` | 409 | "This repository's provider connection is gone. Reconnect it, or remove it." |
| `repository_not_found` | 404 | The repository isn't in this workspace. |
| `subscription_required` | 402 | The workspace plan isn't active. Check **Billing**. |

More fixes are on [Troubleshooting](/platform/support/troubleshooting#indexing-failed-or-stuck).

## Usage and access

Respect the limit or provisioning message shown by the console. Hosted plans have daily push-build allowances as well as build concurrency and operational limits. Uncapped graph size on Pro and Teams does not remove those limits. See [plans and pricing](/platform/support/pricing) for hosted allowances, and the workspace's **Billing** view for its plan.
