Graphify limits how fast you can call Ask, query, and the hosted MCP server, and how much each plan can build, review, and verify. A request over a rate limit returns HTTP `429` with the code `rate_limited`. Wait a few seconds and retry.

<Note>
This page covers Graphify, the hosted product. Graphify Local, the open-source CLI, has no rate limits; it runs on your machine.
</Note>

## Request rate limits

These are the default limits on every plan. They may change as we tune the service. Teams and Enterprise workspaces can get higher limits; [contact us](/platform/support/pricing#enterprise) if you need more.

| Operation | Limit |
| --- | --- |
| Ask requests | 30/minute |
| Query requests | 120/minute |
| MCP requests | 240/minute |
| Test impact requests | 60/minute |

Ask, query, and test impact limits apply per workspace. The hosted MCP limit applies per client IP address. See [Hosted MCP limits](/platform/hosted-mcp#hosted-mcp-limits) and [Test impact analysis](/platform/test-impact#limits).

## Memory limits

| Operation | Limit |
| --- | --- |
| Memory ingestion | 2,000 ingests/day |
| Stored memory | 10,000 turns/repository |
| Memory consolidation | 1 concurrent job/workspace |

## Plan allowances

Builds, reviews, and verification runs are counted per repository or per workspace, depending on the allowance. [Plans and pricing](/platform/support/pricing#hosted-plan-allowances) has the full table for each plan.

All hosted plans allow 1 index build at a time per repository and 10 across a workspace.

## What a 429 looks like

```json 429 Too Many Requests
{
  "error": {
    "code": "rate_limited",
    "message": "Too many requests. Please slow down."
  },
  "meta": {
    "correlationId": "…"
  }
}
```

The response has no `Retry-After` header. Back off and retry:

1. Wait 2 seconds, then retry the same request.
2. If it fails again, double the wait each time, up to about 60 seconds.
3. Add a little random jitter, so parallel agents do not retry in step.

The usual cause is an agent calling `query_graph` or Ask in a tight loop. Tell the agent to reuse the answers it already has.

## Other limit responses

| Status and code | Meaning | What to do |
| --- | --- | --- |
| `429` `rate_limited` | Too many requests in a short time. | Back off and retry, as above. |
| `402` `subscription_required` | The feature needs a paid plan. | Check **Billing** in the console. |
| `409` `seat_limit_reached` | Every Teams seat is assigned. | Buy more seats in **Billing**, or remove a member. |

The console shows plan limits as messages:

| Message | What it means |
| --- | --- |
| **Monthly indexing allowance used** | The workspace used this month's indexing allowance. It resets at the start of next month. |
| **Daily build limit reached** | The repository used today's automatic builds. It resets at 00:00 UTC. |
| **Repository too large for this plan** | The newest version was not published. The last published version still works. |
| **Monthly reviews used** | The plan's reviews for this month are used. |

Include the `correlationId` from the response, or the `X-Correlation-ID` header, when you contact support. It lets the team find your request.

## Need more capacity

Pro and Teams raise build, review, and verification allowances; see [Plans and pricing](/platform/support/pricing). For higher request limits, on Teams or Enterprise, or for your own deployment, [contact us](/platform/support/pricing#enterprise).
