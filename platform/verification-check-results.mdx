**Read the title, know the outcome.** The check title says how many changed functions were verified. Open the check for one result per function. It's advisory: `success` only when every changed function is Proven same, otherwise `neutral`, never `failure`.

## Every check title, decoded

<AccordionGroup>
  <Accordion title="Proven: N/N PR-changed function(s) behavior-preserving" icon="circle-check">
    Every changed function was Proven same. The check is `success`. Nothing to do, but a proof means "same as before", not "correct".
  </Accordion>
  <Accordion title="Behavior change detected in N function(s)" icon="circle-alert">
    At least one changed function returns a different result for some input. Open the check, find the input, and decide if the change was intended.
  </Accordion>
  <Accordion title="Distinguishing input found (unconfirmed)" icon="circle-help">
    An input looks like it differs, but replaying it didn't confirm it. Run both versions on it before acting. It may be a false alarm.
  </Accordion>
  <Accordion title="X/Y verified · no divergence found (sampled, not a proof)" icon="circle-dot">
    No differences, but at least one function is **No change found**, not Proven same. Good evidence. Add tests that cover more inputs.
  </Accordion>
  <Accordion title="X/Y verified · Z not verified (reasons)" icon="circle-minus">
    Some functions weren't verified. Review them by hand or with tests. See [not verified reasons](#not-verified-reasons).
  </Accordion>
  <Accordion title="X/Y verified · formal verification incomplete" icon="circle-x">
    A function hit an error. Use **Re-run check** in the Console. If it keeps failing, contact support.
  </Accordion>
  <Accordion title="No PR-changed functions were verified" icon="circle-off">
    The run verified none of the changed functions. This isn't a pass. Check the function list for reasons.
  </Accordion>
  <Accordion title="Formal verification did not run" icon="circle-slash">
    No supported files changed, or only test files did. See [when it doesn't run](/platform/verification#when-it-doesnt-run).
  </Accordion>
</AccordionGroup>

## Act on each result

| Result | GitHub / API | Next step |
| --- | --- | --- |
| **≠ Behavior changed** | Behavior change (`distinguished`) | Intended? Add a test for it. Not? Fix and push. The input is shown as **reproduced** or **unconfirmed**. |
| **= Proven same** | Proved equivalent (`equivalent`) | None. |
| **≈ No change found** | No divergence sampled (`may_equivalent`) | Evidence, not proof. Add tests for more inputs. |
| **? Not checked** | Abstained (`unsupported`) | Review or test it as usual. |
| **! Couldn't run** | Errored (`error`) | **Re-run check**. See **Technical details**. |

You may also see **No changed functions to compare** (functions were only added, deleted or renamed) or **Skipped** (the check didn't run).

## Not verified reasons

| Reason | Means |
| --- | --- |
| `vacuous` | The check never exercised the function. |
| `unsupported`, `error` | **Not checked** or **Couldn't run**. |
| `witness not reproduced` | A differing input didn't reproduce in the sandbox. |
| `over cap`, `budget` | The run hit its function or time limit first. |
| `not reported` | No result came back. |

<Note>
**Context functions** are unchanged functions checked alongside the change. They never count toward X/Y, but a behavior change in one still keeps the check `neutral`.
</Note>
