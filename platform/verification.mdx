Graphify formally verifies the functions a pull request changes. For each one, it proves the new version still behaves like the previous version, or it shows you an input where the two give different results. The result appears as a separate GitHub check named **Graphify Formal Verification**, and in the **Formal Verification** view in [Graphify](https://app.graphify.com).

## How it works

<Steps>
  <Step title="Find the changed functions">
    Graphify compares the pull request's head commit with its base and picks out the functions the pull request changed.
  </Step>
  <Step title="Compare old and new">
    For each changed function, Graphify checks whether the new version returns the same result as the previous version for the inputs in scope. The previous version is the reference, not a written spec.
  </Step>
  <Step title="Report a verdict per function">
    Each function gets a verdict: proved equivalent, behavior change (with the input that differs), sampled but not proven, abstained, or errored. The check title sums them up. See [Understand the result](#understand-the-result) for what each one means.
  </Step>
</Steps>

<Note>
**What a pass means.** A passing check means every function this pull request changed was proved to behave like its previous version, within the bounds the proof covers. It does not mean the code meets your requirements: if the old version had a bug, an equivalent new version has the same bug.

- **It never blocks a merge.** The check is advisory. It shows `success` only when every changed function is proved equivalent, and `neutral` in every other case, including a behavior change. It never shows `failure`.
- **Sampled is not proven.** "No divergence found (sampled, not a proof)" means the tried inputs matched. It is evidence, not a proof.
- **A check that never ran the function doesn't count.** If verification never exercised a function, that function is counted as not verified.
- **Each run has a budget.** A run checks a limited number of functions within a time limit. Functions over the limit are listed as not verified, with the reason in the check title.
- **Only changed functions count.** Unchanged functions checked alongside the change are listed separately as context and are not part of the score.
</Note>

## Supported languages

| Language | File extensions |
| --- | --- |
| Python | `.py` |
| JavaScript and TypeScript | `.js` `.mjs` `.cjs` `.jsx` `.ts` `.tsx` `.mts` `.cts` |
| Go | `.go` |
| Java | `.java` |
| C, C++, CUDA and Metal | `.c` `.h` `.cc` `.cpp` `.cxx` `.hh` `.hpp` `.hxx` `.cu` `.cuh` `.metal` |
| Rust | `.rs` |
| COBOL | `.cbl` `.cob` `.cpy` `.cobol` |

A function in a supported language can still get an **Abstained** verdict when the verifier can't analyze it within its supported domain or budget.

## When it doesn't run

Graphify posts a neutral **Formal verification did not run** check, with the reason, when:

- the pull request changes no files in a supported language, or
- the pull request only changes test files, such as files in `tests/` or `__tests__/`, `test_*.py`, `*_test.go`, or `*.test.ts` and `*.spec.ts`.

In both cases there is no changed product code to compare. If you expected a run and see nothing, check that **Formal verification** is turned on for the repository in [Repositories and builds](/platform/repositories).

## Inspect a verification run

<Steps>
  <Step titleSize="h2" title="Choose the repository">
    Use the **Repository** filter or select **All repositories** to see workspace runs.
  </Step>
  <Step titleSize="h2" title="Open a run">
    Check the pull request and commit, then expand the run to inspect its outcome and per-function results. A finished run can contain a mixture of outcomes.
  </Step>
  <Step titleSize="h2" title="Follow the evidence">
    Inspect the source file, function, and verdict. For a behavior change, the detail can include the distinguishing input and the old and new values. An abstention or failure includes its reason when available.
  </Step>
  <Step titleSize="h2" title="Return to the change">
    Use **Open pull request** or the commit link to investigate the implementation. When a run has finished, **Re-run verification** can queue another attempt; queued and running attempts cannot be rerun simultaneously.
  </Step>
</Steps>

## Understand the result

| Result | What it means |
| --- | --- |
| **Proved equivalent (bounded)** / `equivalent` | The proof method established equivalence within its supported model or analysis bounds. |
| **Behavior change** / `distinguished` | An input distinguishes the implementations. Inspect whether the witness was reproduced in the sandbox or remains unconfirmed. |
| **No divergence sampled (not proven)** / `may_equivalent` | The exercised inputs showed no difference. This is empirical evidence, not a proof. |
| **Abstained** / `unsupported` | The method could not analyze the function within its supported domain or budget. |
| **Errored** / `error` | Verification failed to produce a valid result for the function. |

**Completed** describes a run's lifecycle; it does not mean every function was proved equivalent. Queued, verifying, failed, cancelled, skipped, and expired runs also retain their own status. A run that verified no functions does not imply the change passed.

## Configure and use verification

Repository controls include a **Formal verification** setting for pull requests. Use [Repositories and builds](/platform/repositories) to check repository configuration and indexing before investigating missing runs.

When Graphify supplies a distinguishing input, use it to reproduce the difference and create a regression test. Review whether the changed behavior was intentional before deciding what to change.

[Learning](/platform/learning) tunes advisory review feedback only. It cannot change proof verdicts or hide a witness from the verifier.

## Scope of a proof

Verification is function-level and differential: the previous implementation is the reference. It does not establish that the application meets its intended requirements. Read bounds, unsupported cases, and reproduction status with the result.

For the separately installed enterprise CLI, the website's [verification reference](https://graphify.com/docs/verification) documents `verify-edit` and gate configuration. Those commands are distinct from the hosted console workflow and the public open-source CLI.
