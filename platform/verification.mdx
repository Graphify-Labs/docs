**Know your change kept its behavior.** Graphify checks every function a pull request changes against its previous version. It either proves the two behave the same, or shows you an input where they differ.

<CardGroup cols={2}>
  <Card title="Prove it behaves the same" icon="shield-check">
    Each changed function is compared with its previous version, not a written spec.
  </Card>
  <Card title="See the exact input that differs" icon="crosshair">
    A behavior change comes with the input, the old result and the new result.
  </Card>
  <Card title="Merge on your terms" icon="git-merge">
    The **Graphify Formal Verification** check is advisory: `success` or `neutral`, never `failure`.
  </Card>
  <Card title="Use it on every plan" icon="badge-check">
    Daily run limits depend on your plan. See [pricing](https://graphify.com/pricing).
  </Card>
</CardGroup>

## How it works

<Steps>
  <Step title="Find changed functions">
    Graphify compares the head commit with the base.
  </Step>
  <Step title="Compare old and new">
    It checks that the new version returns the same result as the old one for the inputs in scope.
  </Step>
  <Step title="Report one result per function">
    The GitHub check and the **Formal Verification** page in the Console show the results.
  </Step>
</Steps>

## Five plain answers

| Result | Means |
| --- | --- |
| **≠ Behavior changed** | Old and new give different results on the same input. |
| **= Proven same** | Same result for every input in the range checked. |
| **≈ No change found** | Same results on every input tried. Evidence, not proof. |
| **? Not checked** | Couldn't compare this function. Tells you nothing. |
| **! Couldn't run** | The check failed. Says nothing about your code. |

GitHub names, check titles and next steps: [Read a verification check](/platform/verification-check-results).

## What a pass proves

A check passes only when every changed function is **Proven same**, within the bounds the proof covers.

<Warning>
"Same as before" isn't "correct". If the old version had a bug, an equivalent new version has the same bug.
</Warning>

<AccordionGroup>
  <Accordion title="Fine print" icon="info">
    - A function the check never ran counts as not verified.
    - Each run checks a limited number of functions within a time limit. Functions over the limit are listed as not verified.
    - Unchanged functions checked alongside the change are listed as context and don't count toward the score.
    - **Completed** is a run's lifecycle status. It doesn't mean every function was Proven same.
  </Accordion>
</AccordionGroup>

## Supported languages

| Language | Extensions |
| --- | --- |
| Python | `.py` |
| JavaScript, TypeScript | `.js` `.mjs` `.cjs` `.jsx` `.ts` `.tsx` `.mts` `.cts` |
| Go | `.go` |
| Java | `.java` |
| C, C++, CUDA, Metal | `.c` `.h` `.cc` `.cpp` `.cxx` `.hh` `.hpp` `.hxx` `.cu` `.cuh` `.metal` |
| Rust | `.rs` |
| COBOL | `.cbl` `.cob` `.cpy` `.cobol` |

A supported function can still come back **Not checked** if it's outside what the verifier can analyze or over budget.

## When it doesn't run

Graphify posts a neutral **Formal verification did not run** check when the pull request changes no supported files, or only test files (`tests/`, `__tests__/`, `test_*.py`, `*_test.go`, `*.test.ts`, `*.spec.ts`).

Expected a run? Check that **Formal verification** is on in [Repositories and builds](/platform/repositories).

## Dig into a run

<Steps>
  <Step title="Pick a repository">
    Use the **Repository** filter, or **All repositories**.
  </Step>
  <Step title="Expand a run">
    See the pull request, commit and per-function results. A run can mix results.
  </Step>
  <Step title="Follow the evidence">
    A behavior change can include the input and the old and new values. **Technical details** shows the raw verdict.
  </Step>
  <Step title="Act on it">
    Use **Open pull request**, or **Re-run check** once the run has finished. Turn a distinguishing input into a regression test.
  </Step>
</Steps>

<Note>
[Learning](/platform/learning) tunes review feedback only. It can't change verdicts. The enterprise CLI's `verify-edit` is documented separately in the [verification reference](https://graphify.com/docs/verification).
</Note>
