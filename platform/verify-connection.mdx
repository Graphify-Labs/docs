Use this page after you [connect your agent](/platform/quickstart). It takes about two minutes. You check three things in order: the server is connected, the agent can call Graphify's tools, and the agent picks them for code questions.

## In Graphify: connection status and starter tasks

On **Connectors → MCP**, the **Try a query** step shows a live connection status:

| Status | Meaning |
| --- | --- |
| Waiting for your agent's call. Still waiting? Run any Graphify tool in your agent. | No tool call from your account is on record for this workspace in the last 30 days. After you check the list, you can select **My agent returned repositories**. |
| Connected. Graphify just received a tool call from your account. | A tool call reached this workspace while the page was open. |
| Connected. Last tool call from your account: … | A tool call from your account already reached this workspace in the last 30 days. |
| Connected. Graphify has a record of a tool call from your account. | Graphify recorded a call from your account, but not when it happened. |
| Recent activity from your account is in … | The latest call was in a different workspace. Switch with `set_workspace`, or use a token from this workspace. |

When the status is **Connected**, Graphify hides **My agent returned repositories** and unlocks **Try a repository task**.

The same page has a **Connect your agent** card with install steps for your client, a rules block you can copy into `AGENTS.md` / `CLAUDE.md` / your client's rules file, and (once a repository is indexed) **Try it on your repository** starter tasks drawn from your code. Starter tasks are one-click handoffs; after a task finishes you can **Run again** for a fresh receipt instead of replaying a consumed one.

## Step 1: Check the server is connected

Your client should list a server named `graphify` at `https://api.graphify.com/mcp`, signed in, with its tools showing.

| Client | Where to check | Connected looks like |
| --- | --- | --- |
| Claude Code | Run `claude mcp list` in a terminal, or `/mcp` inside Claude Code. | `graphify` shows **Connected**. |
| Claude.ai and Desktop | In a chat, select **+**, then **Connectors**. | **Graphify** is on for that chat. See [Graphify for Claude](/integrations/claude-ai). |
| Cursor | Open **Customize** in the sidebar and find `graphify`. With the Cursor CLI, run `agent mcp list`. | `graphify` is on, with its tools listed. **Needs login** means you haven't signed in yet. |
| Codex | Start a new session and run `/mcp`. | `graphify` is listed with its tools. |
| VS Code | Run **MCP: List Servers** from the Command Palette. | **Graphify** is running. In agent chat, its tools are turned on in the tools picker. |

Other clients have their own MCP panel. See [Integrations](/integrations/overview) for each one.

<Note>
A listed server isn't proof the agent can read your repositories. Step 2 checks that.
</Note>

## Step 2: Run three test prompts

Open a new agent chat and paste each prompt. Your client shows each tool call in the chat, usually with its name and arguments. Check that a Graphify tool ran, not a file search.

| Prompt | Tool you should see | A good answer |
| --- | --- | --- |
| `Use Graphify to list my repositories. If the tool fails, show the error.` | `list_repositories` | Your indexed repositories, with their index status. |
| `Using Graphify, who calls <function> in <repo>? Cite file paths.` | `graphify_callers`, often after `graphify_find` | Callers with file paths you can open and check. |
| `Using Graphify, what could break if I change <function>, and which tests cover it?` | `graphify_impact` with `include_risk`, or `graphify_tests_for` | Connected code, hotspot files, and linked tests. |

Replace `<function>` with a function you know in a repository from the first answer. If you belong to several workspaces and the list looks wrong, ask the agent to run `list_workspaces`, then `set_workspace`.

Then ask a code question without naming Graphify, such as `What calls <function>?`. If the agent searches files instead, add the always-on rule in [Setup for AI agents](/for-agents#setup-for-ai-agents), step 5.

## Step 3: Fix what's wrong

| Symptom | Fix |
| --- | --- |
| **Needs login** or **Needs authentication** next to `graphify` | You haven't signed in. Claude Code: `/mcp`, select **graphify**, choose **Authenticate**. Codex: `codex mcp login graphify`. Cursor: select **graphify** and finish the browser sign-in. VS Code: restart the server in **MCP: List Servers** and sign in. |
| `graphify` is missing from the list | Check the config file is valid JSON (or TOML for Codex) and the URL is `https://api.graphify.com/mcp`. Then reload the client or start a new session. |
| The agent asks for an API key | Graphify uses OAuth sign-in, not a key. Check the URL is the hosted one above. |
| `list_repositories` is empty | No repository is indexed in this workspace. Index one in the [Console](https://app.graphify.com?utm_source=docs&utm_medium=link&utm_campaign=platform-verify-connection), or switch workspace with `set_workspace`. |
| A repository is listed but answers are empty | It's still indexing, or it's in another workspace. Wait for **Indexed** on **Repositories** in the Console. |
| The agent used grep or read files instead | Add the always-on rule from [Setup for AI agents](/for-agents#setup-for-ai-agents) to `AGENTS.md`, `CLAUDE.md` or `.cursor/rules/graphify.mdc`. For hooks and stricter rules, see [Make agents use the graph](/cookbooks/make-agents-use-the-graph). |
| Tools are listed but never run | Turn on Graphify's tools in your client's chat, and use a model that can call tools. |
| Every tool appears twice | The server is configured twice, for example in `~/.cursor/mcp.json` and `.cursor/mcp.json`. Remove one. |
| A Cursor cloud agent can't see Graphify | Cloud agents don't read your local `mcp.json`, and they keep their own sign-in. Add and sign in to Graphify for cloud agents at [cursor.com/agents](https://cursor.com/agents). |
| Answers miss today's changes | Graphify serves the indexed default branch. Uncommitted work isn't in it. |
| Claude shows a generic error, or says it couldn't retrieve a result | Wait a few seconds and ask again. If it repeats, see [Claude shows a generic error](/platform/support/troubleshooting#claude-shows-a-generic-error). |
| Only a `graphify_setup` tool appears, or the agent shows **Graphify isn't set up for this account yet** | Create a workspace at [app.graphify.com/onboarding](https://app.graphify.com/onboarding?utm_source=docs&utm_medium=link&utm_campaign=platform-verify-connection), connect GitHub, enable a repository, wait for **Indexed**, then start a new chat and reconnect if needed. |
| The agent says **This workspace has no repositories enabled for agents yet.** | Enable a repository in Graphify, wait for the first index to finish, then rerun the check prompts. |
| The browser shows **Finish setting up Graphify** | Continue setup with the same account you used to connect, create a workspace, enable a repository, then return to the client and rerun the check prompts. |

More fixes are in [Graphify MCP](/platform/graphify-mcp#fix-common-problems) and [Troubleshooting](/platform/support/troubleshooting).

## Prove it after a session

At the end of a task, ask:

```text
List every Graphify tool call you made in this session, with what you passed. If you made none, say so.
```

The calls it names should match the tool calls in the chat. To count calls across Claude Code sessions, see [Make agents use the graph](/cookbooks/make-agents-use-the-graph#step-6-prove-the-agent-used-the-graph).
