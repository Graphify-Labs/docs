Your team opens more pull requests than anyone can review in depth. A diff shows the changed lines, but not the callers they reach or the other open pull requests that touch the same code. Graphify reviews each pull request against the graph of the repository and shares that graph with everyone in the workspace.

This walkthrough uses the open-source [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify) repository.

## Walk through it

<Steps>
  <Step title="Share the workspace">
    On the Teams plan (minimum 2 seats), repositories and Google Drive sources are shared with everyone in the workspace. See [Plans and pricing](/pricing/overview).
  </Step>
  <Step title="Let each pull request get a review">
    Graphify reviews a pull request when it is opened, reopened, or marked ready for review. After new commits, an owner, member, or collaborator comments `@graphify review` to review the current head. See [Review a pull request](/concepts/review-a-pull-request) and [Pull request reviews](/platform/reviews).
  </Step>
  <Step title="Read the findings together">
    Open **Reviews**, pick the pull request and run, and read each finding with the affected code. Where verification ran, each supported changed function is proved equivalent, shows a behavior change with the input, or has no verdict. See [Read a review and a verdict](/platform/read-a-result).
  </Step>
  <Step title="Teach it what matters">
    Reply with `@graphify wrong <finding>`, `@graphify good <finding>`, or `@graphify suppress <rule>`. The [Learn](/platform/learning) view shows what the team has taught it.
  </Step>
  <Step title="Watch for colliding work">
    Graphify also checks each pull request for cross-branch conflicts with the other open pull requests and gives a merge order. See [Find colliding pull requests](/concepts/colliding-pull-requests).
  </Step>
</Steps>

Reviews and verification are advisory. Neither blocks a merge, so keep your own required checks.

## Do it locally instead

The open-source CLI has no review bot, but it can rank and compare the open pull requests on a clone:

```bash
graphify extract . --code-only
graphify prs --conflicts --repo Graphify-Labs/graphify
graphify prs --triage --repo Graphify-Labs/graphify
```

`--conflicts` groups pull requests that share a graph community. That is a merge-order risk, not a merge order. `--triage` ranks the queue with a model you configure. It needs the [GitHub CLI](https://cli.github.com) signed in. See [Review pull requests locally](/guides/pull-requests) and [Share context with your team](/guides/team-workflows).
